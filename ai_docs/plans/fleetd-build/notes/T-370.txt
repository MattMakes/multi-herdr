Security rule for your git commands: git merge-tree and each other merge command can start a merge driver or a filter that the repository config or .gitattributes names. That is code of the project, and it must never run with the rights of fleetd. Run each git command with -c core.hooksPath=/dev/null and with the merge drivers and filters of the project turned off (for example an override of merge.<driver>.driver and filter.<name>.* is not possible for unknown names, so use a clean config: GIT_CONFIG_NOSYSTEM, GIT_CONFIG_GLOBAL=/dev/null, and -c core.attributesFile with no project drivers, or run the command in the platform sandbox primitive of ticket 17). Choose the way that you can prove, and add 1 attack test: a repository whose .gitattributes and config name a merge driver that writes a marker file; the job runs; the marker does not exist.
