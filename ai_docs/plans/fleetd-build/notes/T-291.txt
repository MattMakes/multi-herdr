Rule from the review of T-287 (worktree_remove): the claim that adopts a rescued tree must refuse (or wait) while a worktree_remove run of that tree is queued or running. The remove job reads the ledger row again as its last fact, but a claim in the last 20 ms can race it. Close the race in the ledger: the claim and the remove job must not both pass. For example the remove job moves the tree to a state "removing" through transition() in its own transaction before the git command, and the claim refuses a tree in that state. Add a test that runs the 2 in each order. A lost tree with work is the worst fault of this phase.
