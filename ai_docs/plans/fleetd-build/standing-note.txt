[orchestrator] Standing rules for each builder of the run fleetd-build, in addition to your ticket. (1) Schema: do not trust a schema number in your ticket. Read VERSION in crates/horch-core/src/taskledger/schema.rs. Phase 1 added version 8 on this branch, and each later phase adds the next one. The main branch also has its own version 8; a later merge task renumbers the fleetd steps. Keep each schema number in 1 constant and do not write the number in other places. (2) Before horch ledger finish, also run the guard tests, because the Check of a ticket is narrow: cargo test -p horch-core --test nfr --test arch_scan --test architecture_doc. If your change makes one fail (for example a new crate or a new type name), correct the list or the name in the same ticket; that is permitted outside Own. (3) While you wait for a long run, run horch ledger progress each 5 minutes. (4) A Linux run in Docker is optional and runs only the tests of your ticket, never the whole workspace; remove the Docker volume after it. (5) Windows code cannot be compiled here: keep it small, read it twice, and name each Windows risk in your done summary.
 (6) SPEED RULE from the operator: the code review of your task is deferred to the end of the build. Your finish runs no code-sweep. Before horch ledger finish, run only the Check of your ticket and the guard tests. Do NOT run the whole workspace suite yourself, and do not run a test many times to prove it; the phase gate runs the whole suite and corrects red tests. Do not add work that the ticket does not ask for. Send QUESTION only when you cannot continue: for a small reversible choice (1 more file outside Own for a pin or a caller, a test helper), decide, do it, and name it in the done summary. (7) Keep the done summary complete: each file outside Own, each deviation, each risk. The end review reads it.
8. TIME LIMIT RULE: use a time limit on each test command (for example a 20 minute limit for 1 test file). A test run with no end hangs: stop it, find the test with -- --nocapture --test-threads=1, and fix the cause. Known causes: a test World that drops its TempDir before its ChannelServer, and a wait with no time limit.
9. HOST RULE: macOS holds each new test binary at launch for 10 minutes or more, and the disk is small. Run only the test files of your ticket. Do not run a whole-crate or whole-workspace test run. Send horch ledger progress each 5 min while a test or finish runs. If the base is red for a cause that is not yours, name it and continue. Each test fixture that adds a task needs an idea in flight: call schema::run_idea after runs::create (FR-12).
