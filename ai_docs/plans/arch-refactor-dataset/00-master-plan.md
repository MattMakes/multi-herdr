## Context

PR #14 (`combine-open-prs`, head `575c2c2`) made multi-herdr, the Rust `horch` workspace, into an execution platform. It has:
- teammates and five harnesses
- the worker and session lifecycle, messaging and tiling
- usage and cost accounting, telemetry, and quota-aware routing
- effort-matrix personas and hermetic e2e tests

The operator gave two specs to build on it, on **one new branch off `combine-open-prs`**:

- **Spec A, the Architecture Refactor** (phases 0–12). It makes ownership explicit: teammate, harness, model, worker, task, execution, session, pane and skill. It uses a functional core with an imperative shell, no ambient env in domain code, and pure planning. Skills become first-class and versioned through an internal marketplace. Old ledgers and offline built-ins are preserved.
- **Spec B, Dataset & Competitive Execution Mode.** A separate, explicitly expensive `multi-herdr-dataset` entrypoint that composes the *same* kernel:
  - preflight, then a plan;
  - N candidates in isolated worktrees from one base SHA;
  - validation, then a background blind judge;
  - deterministic winner policy, optional promotion, then export.

  Spec B's own phase 1 (a refactor) is subsumed by Spec A. Its phase 8 (training Laya) is out of scope.

Spec A §18 says competition must be *a composition of ordinary executions*. So **Spec A goes first (A0–A12), and Spec B is built on top (B1–B6).** The project identity carries through every phase: Rust decides whatever can be decided deterministically, and agents decide only where semantic judgment is needed.

## 2. Key types (summary; full signatures are in the design doc)

- **ids.rs:** a `string_id!` newtype for each of ExecutionId, TaskId, SessionId, WorkerId, RoleName (rejects `/ \ ..` and control characters), SkillId, ModelId, TeammateName, PaneId, WorkspaceId, ExperimentId, RoundId, EventId and JudgmentId. Also `mint_v7(at)` and `Digest([u8;32])`, which displays as `sha256:<hex>` (B1).
- **`RuntimeContext`:**
  - paths: project_dir, state_root, data_root, temp_root, home;
  - herdr: workspace and pane;
  - binaries: roster_override, current_exe, `horch_exe` (sibling, then PATH), and `HarnessBins` + `BinOverrides` (claude, codex, opencode, pi, prime, herdr, sqlite3, ollama, git);
  - settings: clock, tiling, balance_override, quota_file, machine_file, probe_timeout, faults;
  - environment: inherited (`OPENCODE_CONFIG_CONTENT`, `CODEX_HOME`, …) and `worker: Option<WorkerEnv>`.

  It is built from the `EnvSource` trait, either `ProcessEnv` or `MapEnv` for tests.
- **`ExecutionStatus`:** `Planned | Starting | Running | Done | Failed(FailureKind{AgentExited{code}, PaneVanished, TimedOut, Cancelled{reason}, Crashed}) | LaunchFailed{stage, reason}`, with `is_live()` = Starting|Running.
  - **Legacy compatibility:** the on-disk `status` keeps writing `"working"` (Planned/Starting/Running) or `"done"` (all terminal states). The typed status goes in a new optional `state` field. Readers prefer `state` and fall back to deriving from `status`. Old binaries therefore read new ledgers correctly, and a LaunchFailed or Failed record looks "done", never phantom-live.
- **`ExecutionKind`:** `Worker | Orchestrator | Candidate{experiment, round, label} | Judge{round, attempt}`. Plus `SessionMode{Fresh(Option<SessionId>), Resume(SessionId)}` and `TilingMode{Automatic, Disabled}`.
- **`Execution`:** Spec A §4 fields, plus kind, task text, plan, project, `workdir`, workspace, `pane`, history and timestamps.
- **`LedgerRecordV1`:** exactly today's `Record` serde. `tier` stays. It gains optional, skip-if-empty fields: `pane_id, task_id, workdir, experiment_id, round_id, label, state, exit_code, finished_at, skills, routing`.
- **routing:**
  - `ExclusionReason{NotInRoster, Hidden, ReservedTier, TrainsOnInput, PoolBlocked, Unspawnable, EffortUnsupported, HarnessUnavailable, AgentNone, ExcludedByConfig, OverBudget}`.
  - `EligibleEntry{teammate, harness, model, effort, fallback_index, pool, pool_state, verdict}`.
  - Pure functions `eligible_fallbacks()` and `roster_eligibility()`.
  - `RoutingProvenance{requested, resolved, fallback_index, pool, pool_state, reason, mode}`.
  - `RoutingDecision{Spawn | Substitute{requested, resolved, reason} | Refuse{requested, reason, pools}}`, with a DTO that renders the old `Decision` JSON byte-for-byte.
- **execution:**
  - `SpawnRequest`: Spec A §8 fields plus `workdir`, `kind` and `report_to: ReportTarget{Orchestrator, None}`.
  - `ExecutionPlan{execution, worker, launch, skills: SkillActivationPlan, workspace, gate_line}`.
  - Pure `plan_launch()` / `finish_plan()`.
  - `SpawnError{Refused, Plan, LaunchFailed{id, stage, source}}`.
- **harness:** `enum HarnessKind{Claude, Codex, OpenCode, Pi, Prime, None}` with `#[serde(rename="opencode")]`. `Capabilities{caller_minted_session, resume, effort, daemon, exec_policy, skill_exposure, tool_lists, tool_denylist, headless}`. The `Harness` trait has kind, capabilities, validate, prepare (codex rules, prime daemon, skill exposure), build_command (strips FORBIDDEN_ENV) and discover_session (by canonical workdir). Dispatch is by enum through `HarnessKind::adapter()`.
- **workspace:** the `WorkspaceClient` trait covers pane_get, list, split, run, close, agent_prompt, send_text, send_keys and pane_read, plus workspace_create and workspace_close. Implemented by `HerdrClient` (wire DTOs private) and `testing::FakeWorkspace` (call log, injected failures).
- **measure:**
  - `EventEnvelope{schema_version "1.0.0", event_id, kind, occurred_at (RFC3339 ms), actor{Coordinator|Worker|JudgeJob|Operator}, experiment_id, round_id?, execution_id?, idempotency_key, payload (typed; Unknown preserved)}`.
  - `trait Recorder{append(NewEvent) -> Appended{Recorded|Duplicate}}`, implemented by `NoopRecorder` (normal mode) and `JsonlRecorder`.
- **vcs:**
  - The `GitClient` trait covers toplevel, head, current_branch, status_porcelain, version, worktree add/remove/list, commit_all (hooks off, no gpg, deterministic identity), rev_parse, rev_list, diff_numstat, diff_patch (capped), is_ancestor, update_ref_cas, cherry_pick → Clean|Conflict, merge_ff_only and branch_checkout_location.
  - `GitCli` runs with `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C` and FORBIDDEN_ENV stripped.
  - `WorktreeManager{create (idempotent), freeze → FrozenCandidate, remove}`.
- **evaluation:**
  - `Validator::validate(&FrozenCandidate) -> ValidationReport`, implemented by `CommandValidator`, which runs gates from operator config only.
  - `JudgeInput` is an immutable bundle and digest. The label → execution map stays in round state and never enters the bundle.
  - `Judgment` matches Spec B §11 with `deny_unknown_fields`.
  - Pure functions `parse_judgment()` (strict, never repairs) and `decide_winner() -> WinnerOutcome{Winner, NeedsIntervention, Rejected}`.
  - `WinnerPolicy{min_confidence 0.7, tie_break: Disabled (default) | Utility{v}}`.
- **promotion:** `PromotionEngine::promote(&FrozenCandidate, &BranchRef, &PromotionPlan)` returns a `PromotionReceipt{source_shas, dest_ref, dest_before, dest_after, strategy, validation_ids, judgment_id, …}`.
- **teacher:** `DecisionRequest{model, state, questions{id → Question{type: choice|score|noul, instructions, options, criteria}}}` and `DecisionResponse{answers{id → {choice, probabilities, confidence}}, usage}`. `trait DecisionModel { decide() -> Option<DecisionResponse> }`, with `Inert` returning `None`.
- **export row:** `mh.export/1.0.0`, label_policy_version, ids, `state` (task features plus repo, env and base digests), `questions` (`best_worker`: a choice over eligible config ids; per-config `quality` scores), `answers` (empirical winner or null on abstain/tie), eligible_set, planner_propensities, `teacher{id:"none", probabilities:null}`, every WorkerRun, winner, component quality, cost_microusd, latency_ms and outcomes.
- **money** (`usage/money.rs`): stored as `MicroUsd(i64)`, accumulated as `NanoUsd(i128)`. Price $/MTok × 1000 gives n$/token, which is exact for every built-in price. Round half-even once. `cost_source ∈ {price_table@<date>, pricing_file@<sha12>, harness_reported, unpriced}`.

### B5 Promotion (opt-in, OD5)
State machine with OD5: `… → JUDGING_BACKGROUND → DECIDED`. Without promotion (the default), the round goes `DECIDED → CLEANUP → COMPLETE`, recording `winner.selected` with `promotion: not_requested`. With promotion, it goes `DECIDED → revalidate → PROMOTING → PROMOTED | NEEDS_INTERVENTION | REJECTED → CLEANUP → COMPLETE`. `promote <round>` later re-enters at DECIDED. `cmp_03_transition_table` covers both paths.

`GitPromotionEngine`, run by `--promote-to` or `promote <round>`:
1. Check that the worktree HEAD and the branch both equal the frozen SHA. If not, the judgment is stale → REJECTED.
2. Record `dest_before`.
3. Integrate. If `dest_before == base_sha`, fast-forward. Otherwise cherry-pick `base..head` in a temp integration worktree with deterministic identity and dates. A conflict emits `promotion.conflicted` → NEEDS_INTERVENTION, and the worktrees are kept.
4. Revalidate the gates on the integrated commit; a failure → REJECTED.
5. Publish:
   - target not checked out → CAS `update-ref`;
   - checked out and clean → `merge --ff-only` in that checkout;
   - checked out and dirty → NEEDS_INTERVENTION.
6. `promotion.started{dest_before, planned_after}` → publish → receipt via `create_immutable` → `promotion.completed`.

**Restart:** ref == planned_after → write the receipt; ref == dest_before → retry; anything else → NEEDS_INTERVENTION.

`competition/cleanup.rs` removes worktrees **only after a durable receipt** (or at round end when not promoting). Candidate branches are kept (`--prune-branches` is opt-in), and failures emit `worktree.cleanup_failed`. NEEDS_INTERVENTION keeps everything.

CLI: `promote`, `rollback` (CAS back, then `promotion.rolled_back`), `cleanup`.

**Tests:** PRO-01..08 and the crash suite.

## 6. Risks and open items
1. **Build environment.** `static.crates.io` must be allowed, or the gates must run on the Mac. Nothing can be verified until then.
2. **Workspace-trust prompts** may stall interactive candidate panes in new worktree dirs. Mitigations: `--worktree-root`, a preflight warning, and the deadline, which turns a stall into a TimedOut data point. LA-7 decides.
3. **Agents that never run `horch done`** are caught only by the deadline. Idle detection through herdr agent state is deferred.
4. **Strict judge parsing vs LLM code fences.** The parser never repairs. If fences dominate, use `--json-schema` or reword the rubric (LA-8).
5. **Typed statuses in `horch sessions`.** Showing the typed status (failed/launch_failed) to the orchestrator LLM would need a sanctioned golden block in its base prompt; decide at A6. The disk format stays compatible either way.
6. **Disk cost.** N worktrees with separate `CARGO_TARGET_DIR`s are expensive on Rust repos; PRE-02 must estimate it.
7. **System One wire details** (`criteria` semantics) are unverified until Clef is enabled. Rows store `api: "systemone/v1"` so they can be mapped later.
8. **Scope.** 19 phases is a very large branch. Phase commits are cut so stacked PRs can be split out at any boundary.
