## The 19 files

All 19 have the frontmatter the spec lists: `base: fleet-worker`,
`agent: claude`, `permission_mode: auto`, `inherit_plugins: false`,
`mcp_servers: {}`, `disallowed_tools: [Agent]` (the code reviewer also denies
`Edit`, `Write`, `NotebookEdit`), `disabled_skills: [herdr-orchestrator,
herdr-worker]`, `offer_when: ["project.godot"]`, `requires: [godot]`. Phase,
model, effort, `skills:` and `available_skills:` are copied from the 3 wave
tables. `godot-qa-engineer` adds `check`, `debug`, `tdd`; the code reviewer
adds `code-review`.

- Fallbacks: `godot-tech-lead` and `godot-code-reviewer` have
  `fallbacks: [codex-sol]`. The builders and QA have none, with the reason in
  a comment (Godot import writes to the user data directory; Codex runs with
  the network off and `workspace-write`; untried).
- C#: each of the 15 builders except `godot-csharp-engineer` has
  `skills_when: {"*.csproj": [godot-csharp-godot, godot-csharp-signals]}`.
  `godot-csharp-engineer` has both in `skills:`, and `--check` fails a skill
  that is in both lists. QA and the reviewer are not builders and have none.
- Personas: a role paragraph, the domain boundary to the neighbouring seats,
  and the 6 rules of "What every persona must say" in the seat's own words
  (the tech lead owns the context file; the reviewer turns each rule into a
  finding). Some builders add one role line to rule 5 (for example the
  network engineer names the server and client runs).
- `godot-release-engineer` never runs `butler push`, `steamcmd` or a store
  upload, never touches signing keys, and ends at a release plan for the
  orchestrator.
- `brief_description` is at most 120 bytes on every seat (ASCII only).

The files were generated by a scratch script
(`.worktrees/_scratch/godot-opus-86/gen.py`, git-ignored) and committed as
plain files; edit the files directly from now on.
