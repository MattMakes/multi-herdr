# Ubiquitous language: fleetd: the horch fleet control plane

## Shared
**Idea** - A rough request from the operator that 1 fixed state machine moves from captured to merged; only code advances it. _Avoid_: ticket (a ticket enters as a --direct idea), request
**Feature** - 1 sub-orchestrator, 1 feature branch and 1 pull request to the primary branch, holding 1 main idea and its follow-on ideas. The task kind 'feature' is a different thing (H2). _Avoid_: project, epic _(meaning differs by context - see below)_
**Sub-Orchestrator** - The interactive Opus 5.5 agent of 1 feature that clarifies, specifies and plans 1 idea at a time, with a fresh process per phase. _Avoid_: orchestrator, lead
**Assumption** - 1 line in assumptions.md, [confirmed] or [assumed], that the operator approves or revises; the sub-orchestrator can also record its own reversible one. _Avoid_: requirement
**Plan** - The validated plan.yaml of 1 idea: tasks, dependencies, checks, paired judges. No task exists outside a committed plan. _Avoid_: ticket list
**Task** - A planned unit of work from plan.yaml with a kind, a check and an owner path set; it survives many attempts (H1). _Avoid_: job, claim
**Attempt** - 1 run of 1 worker on 1 task (A1, A2, ...), launched through the wrapper and ended by fleetd. _Avoid_: run, session
**Lease** - The time-limited hold of an attempt on its task that renews only on earned activity and pauses during sleep and waiting_quota. _Avoid_: claim, lock _(meaning differs by context - see below)_
**Worktree** - The git working tree that fleetd leases to 1 task before it exists and never removes before its work is landed or rescued. _Avoid_: checkout, workspace
**Rescue Ref** - A verified commit under refs/horch/rescue/ that saves the full state of a tree or an old branch tip before cleanup or rebase. _Avoid_: backup, archive ref (a different ref family)
**Task Branch** - The branch of 1 task that lands on its feature branch through the landing state machine. _Avoid_: worker branch
**Feature Branch** - The branch of 1 feature that collects its landed task branches and reaches the primary branch through 1 pull request. _Avoid_: integration branch
**Primary Branch** - The base branch of a project; main in this repository, not in every project. _Avoid_: main, master, trunk
**Bundle** - 1 candidate made from the feature branch tip plus every ready task branch of that feature, tested once by the fast gate. _Avoid_: batch, merge train
**Fast Gate** - The declared unit-test command of a project that every bundle and every rebased feature branch must pass. _Avoid_: CI, check
**Full Gate** - The fast gate plus the end-to-end tests, run on a feature tip over the current primary branch; a pass goes stale when either tip moves. _Avoid_: CI, e2e run
**Trial Merge** - A merge-tree result between 2 in-flight features, or a feature and the primary branch, recorded in the ledger with no checkout. _Avoid_: dry run
**Resolver Task** - A code-kind task that resolves 1 conflict between stacked features, at most 100 changed lines or 2 files. _Avoid_: merge task
**Judge Task** - A task of kind judge that ranks the misses of 1 judgment-kind task CRITICAL, HIGH, MEDIUM or LOW; it needs no judge itself (H5). _Avoid_: review task, judgment task
**Fallback** - The persona that a worker persona names for use when its provider pool shows a usage limit or an outage. _Avoid_: backup model

## Coined by ddd-code
**Verified Verdict** - The value that only the verification module can create, and the only input that moves a task to done. (context: task-execution)
**Stall Rung** - 1 step of the stall ladder: first doorbell, second doorbell, or end of the attempt. (context: task-execution)
**Awake Instant** - A time reading that counts only awake machine time, used for leases and stall rungs. (context: task-execution)
**Path Claim** - The set of paths a running task owns; 2 running tasks of 1 feature never hold overlapping claims. (context: task-execution)
**Judge Finding** - 1 miss that a judge task reports, with a rank of CRITICAL, HIGH, MEDIUM or LOW. (context: task-execution)
**Judged Tree** - The tree hash that a check, a review or a gate judged; a pass stands only while the tree is the same. (context: integration)

## Ideas context
**Assumption** — 1 line in assumptions.md, [confirmed] or [assumed], that the operator approves or revises; also a reversible assumption that the sub-orchestrator records to answer a worker question (understand N11). _Avoid_: requirement _(differs from the shared meaning — a boundary)_
**Spec** — spec.md and requirements.yaml of 1 idea. Every requirement cites an approved assumption or an operator answer. It is written only after approval, in the phase specifying (FR-10).
**Question** — A worker question to the sub-orchestrator of its feature. It ends as an answer, an own assumption, a revise request, or an escalation to the operator.
**Orchestrator** — Not a role in fleetd. The word survives only in the preserved mail contract tag [orchestrator re #<id>] (discover N3).
**Needs-you list** — The 1 place for everything that waits for the operator (design OR-3, /fleet/needs-you/): approvals, escalated worker questions and escalated tasks. ideas owns it (orchestrator, D15).
_Uses the shared meaning of_: **Idea**, **Sub-Orchestrator**, **Plan**

## Task execution context
**Lease** — The time-limited hold of 1 attempt on its task. It renews only on earned activity and pauses during sleep and waiting_quota (discover N1). _Avoid_: claim, lock _(differs from the shared meaning — a boundary)_
**Check** — The acceptance command of a task. The verifier runs it in the worktree, in the sandbox profile of the worker.
**Done** — A task state that only the verifier sets, from facts on disk. It does not mean landed or merged (understand N4).
**Ready** — A task state: every dependency is done and the task waits for dispatch (discover N6).
**Feature** — A code kind of a task (with quality, refactor and security). It is not the feature of the integration context (discover N2). _(differs from the shared meaning — a boundary)_
**Verification** — The check of 1 attempt's result that decides done: result.json validates, the task check passes in the worker's sandbox, and the review (code kinds) or the paired judge (judgment kinds) passes. It is the only writer of done.
_Uses the shared meaning of_: **Task**, **Attempt**, **Fallback**, **Judge Task**, **Resolver Task**

## Worktree custody context
**Worktree Lease** — Same as Lease in this context: the worktree row that holds 1 worktree for 1 task and 1 owner. It is not the attempt lease of task-execution (decompose N4).
**Orphan** — A worktree, on disk or in git worktree list, that the ledger does not own or whose owner attempt is dead. It is adopted or rescued, never deleted.
**Lease** — The worktree lease: the ledger row written in the same transaction that leases the task, before the directory exists. It holds the worktree for 1 task until its work is landed or rescued. _(differs from the shared meaning — a boundary)_
**Landed** — A worktree state: nothing in the worktree is unique any more, so fleetd may remove it (discover N6).
**Orphaned** — A worktree on disk with no live owner attempt, or with no ledger row.
_Uses the shared meaning of_: **Worktree**, **Rescue Ref**

## Landing and integration context
**Feature** — 1 sub-orchestrator, 1 feature branch and 1 pull request to the primary branch, holding 1 main idea and its follow-on ideas (understand N2). The feature aggregate owns feature-opened to feature-merged (discover N2). _Avoid_: project, epic _(differs from the shared meaning — a boundary)_
**Ready** — A task branch is ready when it is verified and waits for a bundle. A feature is ready when its full gate passed and its pull request can open (discover N6).
**Landed** — A task branch state: the branch is fast-forwarded onto its feature branch after the fast gate passed (understand N4).
**Merged** — A feature fact read from git by content: the feature branch is in the primary branch (understand N4).
**Trial merge result** — The answer of a git merge-tree trial merge between 2 features, or a feature and the primary branch: clean, or the conflicting paths. Coined in connect (assumption A6).
_Uses the shared meaning of_: **Feature Branch**, **Task Branch**, **Primary Branch**, **Bundle**, **Fast Gate**, **Full Gate**, **Trial Merge**, **Resolver Task**

## Worker profiles and adapters context
**Worker Profile** — The teammate file of 1 persona: agent CLI, model, effort, skills, MCP servers, sandbox, writable paths, network, liveness, retry and fallback. Profile is its short name.
**Adapter** — The code for 1 agent CLI that turns a worker profile into the exact flags, environment and files of a launch, and reads its quota and context.
**Persona** — A named worker profile that a plan task names. Every worker persona names a fallback persona on another provider when the roster has one.
**Conformance** — The test that launches 1 adapter and reads back its effective settings (sandbox, context limit, hooks, scrubbed environment). A pass makes the profile healthy.
**Profile** — A named worker profile: the CLI, model, effort, sandbox and permission rules that 1 attempt runs with.
**Healthy** — A profile whose adapter passed its last conformance test. Dispatch does not choose an unhealthy profile.
**Launch environment** — The exact CLI, flags, scrubbed environment, config home files and sandbox profile that worker-profiles resolves for 1 process launch. Coined in connect (assumption A6).
**Start agent process** — The worker-profiles call that starts the fleet-run wrapper of 1 attempt, or 1 sub-orchestrator pane, in its own process group through the platform layer. Coined in connect (assumption A6).
**Fleet-run wrapper** — The horch process role that runs 1 attempt: it sets the private config home, scrubs the environment, maps adapter events and writes heartbeat.json and exit.json (connect A7).

## Fleet runtime context
**fleetd** — The supervised daemon role of the horch binary (horch fleetd): the only ledger writer, which runs the reconcile pass of all 6 contexts every 5 s (organise N1).
**Heartbeat** — The time of fleetd's last full pass, written after each pass. horch fleetd check reads it. It is not the wrapper heartbeat.json of an attempt.
**Platform Layer** — The leaf crate crates/horch-platform: 1 interface with 1 module per OS (mac.rs, linux.rs, windows.rs) for process facts, process group stop, service install and restart, hang detection, file watching, sandboxing, sleep and wake, the command channel transport and the machine probe (PL-2, A19). It is not a bounded context; each context calls it (decompose N7).
**Command Channel** — The local transport on which CLI commands and agents send requests to fleetd. fleetd validates each request and writes the result to the ledger.
**Ledger** — The SQLite file ~/.horch/ledger.sqlite3 in WAL mode: an event log plus derived tables. Only fleetd writes it; each context owns its own tables (understand N17, organise N2).
**Check** — horch fleetd check: the heartbeat check that restarts fleetd when its last full pass is older than 30 s of awake time. It is not a task check.
