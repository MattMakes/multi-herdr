# hark listen: realness

Part of the listen spec. Index: `docs/specs/hark/listen.md`.

## Purpose

`realness` decides between 2 sides: a real recording or professional
production on one side, and cheap audio generated by code (oscillators,
filtered random noise, simple envelopes, algorithmic reverb, beeps) on the
other.

- Acoustic against electronic is **not** the question. Electronic music and
  sound design made by professionals (for example risers and sub drops in
  launch films) are on the real side.
- The score depends on the sound itself, not on its origin. A clean,
  professionally made synthetic tone (a UI sound, a chime, a synth stab) can
  score as code-synthesized.
- When a quiet code-made layer sits under a louder real mix, the score
  usually does not detect it. Judge stems
  and source files.

## Interface

CLI and Python signatures are in the index. Result formats:

### Single file

| Field | Type | When | Meaning |
|---|---|---|---|
| `path` | str | always | the path as given in this call (also for a cached result) |
| `duration` | float | always | seconds judged, 3 decimals |
| `range` | [float, float] | a range was given | file times judged, 3 decimals |
| `p_real` | float or null | always | probability of real or pro-produced, 3 decimals; null when silent |
| `verdict` | str | always | `real or pro-produced`, `uncertain`, `likely code-synthesized`, `silent` |
| `why` | str | always | the main reason in one phrase |
| `evidence` | list of str | always | reasons in words, most important first |
| `summary` | str | always | the paragraph |
| `note` | str | judged | how to read p_real (thresholds, limits) |
| `gain_db` | float | gain applied | the quiet-source gain in dB, 1 decimal |
| `segments` | list | long file | per 4 s window `{start, end, p_real, verdict, why?}` |
| `synth_windows` | int | long file | windows with p_real at or below the clip lo threshold |
| `lean_synth_windows` | int | long file | windows with p_real < 0.5 |
| `p_real_min` | float | long file | the lowest window p_real, 3 decimals |

Segment `p_real` is null and `verdict` is `silent` for a silent window. A
segment's `why` is the first fact (R6) of the side it leans to, when any.

### Many files

`{files, counts, summary}`:

- `files`: one single-file result per media file, in listing order, then one
  error row per given path that names no media.
- Error row: `{path, p_real: null, verdict: "error", why, summary}`. `why` is
  `"<ExceptionType>: <first line of message>"` (at most 200 characters), or
  "no such file or folder", or "no audio or video files in it".
- `counts`: the count of each of the 5 verdict names (zeros included).
- `summary`: "<N> files:" with the counts of real, uncertain and
  synthesized, plus silent and unreadable counts when not 0, and the range
  when one applies to each file.

### CLI behaviour

1. If any given path names no media: print one line per bad path to stderr,
   `hark realness: error: <path>: <reason>`, and exit 1 before judging
   anything.
2. One media file in total: judge it, print the single-file text, exit 0.
3. Several: judge each, print the table, exit 1 when any row is an error,
   else 0.

Single-file text: the summary, then each evidence line prefixed "  - ", then
for long files one line per segment (time span `m:ss.ss-m:ss.ss`, p_real with
2 decimals or "-", verdict, ", leans synthesized" when the verdict is
uncertain and p_real < 0.5, and the window's reason in parentheses unless the
verdict is real), then "  note: " and the note.

Table text: the summary; a rule line with the clip thresholds, the file
thresholds (weakly calibrated) and a reminder to judge a trim of a
multi-take file; a header; one row per file: p_real (2 decimals, or "-"),
the verdict (with " (file)" for long files), the base name, " [N low
window(s)]" when synth windows exist, and the reason.

## Behaviour

1. Load the model file once per process. Missing file: an error that says
   the model is missing and how to train it.
2. With a range: check it (R10). Look up the result cache (key: file
   identity, start, end, the AST flag, model `version`, model `trained`, and
   the cache format version). A hit returns the cached result with `path`
   set to the path of this call.
3. Decode mono audio of the range. Apply the quiet-source lift (R1).
4. Cut it into clips (R2).
5. Score each clip (R3 to R5).
6. No clip scored (all silent): verdict `silent`, `p_real` null, `why` says
   it is silent (no part above -60 dBFS RMS) with its peak, or "exact digital
   silence" when the peak is at or below -199 dB; `evidence` = one line that
   there is nothing to judge.
7. p_real of the file = mean of the scored clips' p_real. The verdict uses
   the clip thresholds for a single clip, the file thresholds for a long file
   (more than 1 clip).
8. Evidence (R8). Short and long summaries (R9). Write the cache.

## Algorithms

### R1. Quiet-source lift

CLAP features change on very quiet input. The gain increases continuously
as the level falls, so no level step changes the result suddenly.

1. rms_db = 20 log10(RMS of the mono clip), peak_db = 20 log10(sample peak).
   Empty input: no gain, rms and peak -200 dB.
2. g = min(-30 - rms_db, -1 - peak_db).
3. If peak_db < -80 or g <= 0: no change.
4. Else multiply the audio by 10^(g / 20). (So the RMS reaches -30 dBFS
   unless the peak would pass -1 dBFS.)

### R2. Clips

- Up to 6 s (by sample count): one clip, the whole sound.
- Longer: 4 s windows with a 4 s hop. When the length is not a multiple of
  4 s, add a last window aligned to the end. When there are more than 2
  windows and the last one starts less than 0.25 s after the one before it,
  drop it (less than 0.25 s of it would be new audio).
- Clip times: `(t0, t0 + 4)` local; reported as file times with the end
  capped at the judged duration.

### R3. Signal measurements

Input: a mono 48 kHz clip x. Output: 13 named values, or none.

1. If x is shorter than 20 ms or its peak is below 1e-7: none (not judged).
2. `silence_frac` = share of samples with |x| < 1e-6 (on the 48 kHz input).
3. y = x resampled to 32 kHz, then divided by its peak (+1e-12). All other
   values use y. So the source sample rate, a codec cut-off above 16 kHz and
   the level do not matter.
4. Framing helper: non-overlapping (or hopped) frames of n samples; when y is
   shorter than n, one frame zero-padded to n.
5. `floor_db`: frame RMS over 640-sample frames (20 ms), r = sqrt(mean
   square + 1e-30), in dB. Value = max(-140, 10th percentile - max).
6. Welch power spectrum of y (Hann window, segment length min(2048, len(y)),
   50 % overlap, density scaling). Keep 40 Hz to 15 kHz. Add 1e-30.
   - `log_flatness` = log10(geometric mean / arithmetic mean).
   - `peakiness_db` = 10 log10(max / median).
   - `line_share` = sum of the k largest bins / total, k = max(1,
     floor(0.01 × bin count)).
   - `bandwidth_khz` = the highest kept frequency whose level is within 60 dB
     of the maximum, in kHz.
7. Short-time spectra: frames of 1024 samples, hop 256, Hann window, power
   |FFT|² + 1e-30, bins from 40 Hz to 15 kHz. Frame energy e = 10 log10(sum
   of bins).
   - Loud frames: e > max(e) - 30. `spec_floor_db` = median over loud frames
     of (10th percentile of the frame's bins in dB - the frame's max bin in
     dB).
   - Active frames: e > max(e) - 50. Quiet frames: active frames with e at or
     below the 25th percentile of active e, when there are at least 8 active
     frames; else all active frames. qs = mean spectrum of the quiet frames
     (of all frames when none). `quiet_flat` = log10(geometric mean(qs) /
     arithmetic mean(qs)).
   - Pure-tone frames: per frame, the strongest bin i (kept 2 bins away from
     the band edges). share = energy of bins i-2..i+2 (the Hann main lobe) /
     frame energy. Tonal frame = active and share > 0.5. `tonal_frames` =
     tonal count / max(1, active count).
   - `pitch_wobble`: NaN unless at least 4 frame triplets (3 consecutive
     tonal frames) exist. Per frame, refine the peak frequency by parabolic
     interpolation on the log power of bins i-1, i, i+1: offset δ =
     0.5 (a - c) / (a - 2b + c - 1e-12) bins, f = f_i + δ × 31.25 Hz. Pitch in
     cents = 1200 log2(max(f, 20)). For each triplet, the second difference
     |c₃ - 2c₂ + c₁|. Value = log10(median second difference + 0.01).
8. `env_resid_db`: 5 ms energy in dB (160-sample frames, mean square +
   1e-30). Frames within 40 dB of the maximum count. With at least 9 such
   frames: trend = a running median of 7 frames (35 ms; edges padded with
   zeros); value = log10(median |energy - trend| over counted frames +
   0.01). Else NaN.
9. `texture_kurt`: band-pass y from 2 to 8 kHz (4th-order Butterworth,
   causal). Envelope = sqrt(centred moving mean of the squared band signal
   over 320 samples (10 ms)) + 1e-9. Normalised signal = band / envelope, at
   samples where the band is non-zero and the envelope is within 40 dB of its
   maximum. With more than 100 such samples: ln(mean(s⁴) / (mean(s²)² +
   1e-30) + 1e-9) (the log of the kurtosis: ln 3 for Gaussian noise, ln 1.5
   for a sine). Else NaN.
10. `crest_db`: over the non-zero samples of y, 20 log10(1 / (RMS + 1e-12))
    (the peak is 1). 0 when all samples are zero.

### R4. Clip score

1. A clip is judged when its RMS is above -60 dBFS and R3 gives values.
2. CLAP audio embeddings of the judged clips (repeat padding; one window
   each, because a clip is at most 6 s). This uses the plain CLAP audio
   embedding (no vocabulary templates are involved).
3. Head logit (both heads): replace NaN inputs by the head's `mean`; clip
   each input to `[clip low, clip high]`; standardise z = (v - mean) / scale;
   logit = z · coef + intercept.
4. Fusion: s = intercept + w_clap × logit_clap + w_signal × logit_signal;
   p_real = 1 / (1 + e^(-s)).
5. Pure-tone rule (R5): when it fires, p_real = min(p_real, 0.03).
6. Facts that fire (R6) and the CLAP evidence line (R8).
7. With `--ast`: AudioSet probabilities of the clip; the 3 most probable of
   the synth classes (Constants) and the 3 most probable classes overall,
   with probabilities, as one evidence line.

### R5. Pure-tone rule

A pure, dead-steady tone (a test tone or bare oscillator) lies outside the
training data, so a rule decides it. It fires when all of:

- `tonal_frames` >= 0.95,
- `line_share` >= 0.9,
- `crest_db` <= 4.5,
- `pitch_wobble` is NaN or <= -1.0.

Then p_real = min(p_real, 0.03), the first fact is a synth fact with
precision 0.99 that names a pure dead-steady tone, and the CLAP line says the
rule decided, with the CLAP head's own score.

### R6. Facts

Each model fact `{feature, side, op, value, precision, support}` fires when
the clip's value of `feature` is finite and passes `op` (`<=` or `>=`)
against `value`. A fired fact is a phrase in words (Constants) plus "(P % of
training clips past this were real/pro)" or "... were synthesized". Fired
facts are sorted by precision descending.

How the facts were made (R12): for each measurement and side, take the
weakest threshold for which 90 % or more of the clean training clips beyond
it are on that side, and 25 or more clips are beyond it. Digital silence is never a fact.

### R7. Digital-silence line

Exact digital silence says little, because library recordings that were
edited or gated also contain it. It is context, never a verdict reason.

- Value v = `silence_frac`. If v < 0.02, or no `silence_base` row has
  `at_least` <= v: no line.
- Else take the last row with `at_least` <= v. The line states v as a
  percentage, that it is weak evidence (edited, gated or synthesized), and the
  row's shares of real and synthesized training clips with at least that
  much.

Percentages print with 1 decimal when strictly between 0 and 9.5 %, else as
integers.

### R8. Evidence and reasons

Representative clip: when the file's p_real >= 0.5, the scored clip with the
highest p_real; else the one with the lowest. Its side = real when p >= 0.5,
else synth.

CLAP evidence line of a clip: the head score with sign and 1 decimal,
"toward real" (score >= 0) or "toward synthesized"; the closest of the 12
prompts by cosine with the clip embedding (prompts are embedded as plain CLAP
text, no templates), its side and cosine; the best prompt of the other side
and its cosine; and that the prompt cosines only add context and do not decide.

Evidence list, in order:

1. Long file only, first: the evidence comes from the most real- (or
   synthesized-) sounding window, with its time span and p_real.
2. The CLAP evidence line of the representative clip.
3. Up to 3 fired facts of its side.
4. Up to 1 fired fact of the other side, prefixed "but: ".
5. The digital-silence line, when any.
6. The AST line, when `--ast`.
7. When gain >= 3 dB: a quiet-source line with its RMS, peak and the gain.
8. When the signal head's fusion weight is not 0: the fusion weights and the
   signal head score. Else, when any fact or silence line was listed: that the
   measurements are context, not votes, because the signal head's fusion
   weight is 0.

`why`, short sound: "pure-tone rule (the CLAP head alone: S)" when the rule
fired, else "CLAP head score S (toward real / synthesized)"; then, when not a
pure tone and a fact of the side fired, "; <first such fact>".

`why`, long file: "<N> of <M> windows lean synthesized (p_real < 0.5); mean
CLAP head score S", plus the number of windows decided by the pure-tone rule
when any.

### R9. Summaries

p_real in text: 2 decimals; 3 decimals when the 2-decimal text would equal a
threshold that the true value is not equal to (so 0.168 prints as 0.168, not
0.17, next to lo 0.17).

- Short: "<name>: <verdict> (p_real P; clip thresholds lo L / hi H): <why>."
  `note` states: the calibration of p_real comes from held-out clips (about
  92 % precision at lo and at hi); the score depends on the sound, not its
  origin; the training data; the location of the evaluation.
- Long: "<name>: <verdict> (p_real P, mean of M 4 s windows; file thresholds
  lo L / hi H, weak calibration): <why>." Then, when windows lean
  synthesized: their merged time spans (touching windows merge; at most 6
  spans, then "...") and the count and spans of windows at or below the clip
  lo threshold (or "none at or below ..."). When no window leans
  synthesized: the lowest window p_real, and a statement that a quiet code-made
  layer can still be present below a louder real mix. `note` states: the file
  p_real is the window mean; the file thresholds were set on held-out long
  files (their count and the small number of synthesized ones, so the
  calibration is weak); the window calibration comes from held-out 4 s
  clips; the windows detect spans that are fully
  code-synthesized; the provenance limit.
- `<name>` is the base name, plus `[m:ss.ss-m:ss.ss]` when a range was given.

### R10. Range checks

1. start < 0: value error "start must be >= 0 s".
2. end <= (start or 0): value error "end must be greater than start".
3. start >= the probed duration (when the probe knows it): value error naming
   the file and its length.

### R11. Verdict

    verdict(p, thresholds) = real or pro-produced     if p >= hi
                             likely code-synthesized  if p <= lo
                             uncertain                otherwise

Clip thresholds: lo 0.17, hi 0.77. File thresholds: lo 0.40, hi 0.77.
Segments always use the clip thresholds. So one p_real value can give
one verdict for a short clip and another for a long file. Every summary names the
thresholds it used.

### R12. Training (rebuilds the model file)

Data:

- Labels: 1 = real recording or professionally produced; 0 = synthesized in
  code.
- A training clip is the same unit that inference scores: the whole sound
  when it is 6 s or shorter, otherwise one 4 s window. Long real recordings give evenly spaced 4 s windows (music 4
  per kept file, ambience 2, others 1, with a margin of 5 s for music and 0.5
  s otherwise); long one-shot recordings also give up to 2 one-shot events
  (onset to the next onset at least 0.25 s later, at most 1 s, loudest
  first, RMS above -50 dBFS). Films give every 4 s window. Windows with RMS
  below -60 dBFS are skipped.
- Every clip has a CV group: for real clips, its asset category (ambience,
  foley, garden, keyboard, magic, motion, toy, music) or `film`; for
  synthesized clips, its family (a synth engine, a retired synthesized
  score, generic code generators). Scheme M splits music into 4 groups by
  provider.
- A recording that sits in two category folders is kept in the first group
  only.
- Augmented training copies (roughly 50 % of the clean clips, picked by a hash
  of the clip id, with randomised parameters): synthesized clips get a
  coloured noise floor (-85 to -50 dBFS RMS; white, pink or brown; never a
  real room tone; 45 %), a short excerpt (0.08 to 0.4 s near the peak; 25 %)
  or a lossy codec round trip (MP3 96 / 128 / 192 kbps, Vorbis q3 to q6, AAC
  128 kbps; 30 %); real clips get gating to digital silence (block 5 to 20
  ms, threshold -55 to -30 dB re peak; 35 %), a short excerpt (35 %) or a
  codec round trip (30 %). Augmented copies are only trained on, never
  scored.

Sample weights: the total weight of each class is 1, divided equally over its
groups, then equally over the clips of a group; an augmented clip weighs
0.35 of a clean one. Weights are rescaled to sum to the clip count.

Head fit:

1. Replace NaN by the column mean. Clip each column to its 0.5 and 99.5
   percentiles (stored as `clip`). Standardise with the column mean and std
   + 1e-6 (stored as `mean` and `scale`).
2. Weighted L2 logistic regression: minimise
   C × Σ wᵢ log(1 + e^(-sᵢ mᵢ)) + ½ |β|², with sᵢ = ±1, mᵢ = xᵢ · β + b,
   free intercept b (L-BFGS-B, up to 3000 iterations).
3. The signal head's coefficients are bounded to their physical sign:
   positive for `floor_db`, `spec_floor_db`, `log_flatness`, `bandwidth_khz`,
   `quiet_flat`, `pitch_wobble`, `env_resid_db`, `texture_kurt`, `crest_db`
   (larger reads as a recording); negative for `silence_frac`,
   `peakiness_db`, `line_share`, `tonal_frames`. So a measurement never votes
   in the direction opposite to the physics, because of a property of the data set.
4. C for the CLAP head is chosen from 0.001, 0.003, 0.01 by inner grouped
   cross-validation (5 folds: sorted group names dealt round-robin), by the
   weighted log loss on clean clips. C for the signal head is 0.1.
5. Fusion: a logistic regression (C = 1, coefficients bounded >= 0) on the
   inner out-of-fold head logits of the clean clips. Then refit both heads
   on all training data.

Thresholds (from held-out predictions of scheme M, R13):

- Precision target 0.925.
- hi = the lowest p above which (sorting by p descending, cumulative
  precision of real) at least 92.5 % are real: the p of the last position
  where the cumulative precision is >= 0.925. Clamped to [0.5, 0.95],
  2 decimals.
- lo = the same from the bottom for synthesized, clamped to [0.05, 0.5],
  2 decimals.
- File thresholds: the same rule on long sources (sources with at least 2
  windows; file p = mean window p), then hi = max(file hi, clip hi) and
  lo = max(file lo, clip lo).

Also stored: `facts` (R6 rule on the clean clips), `silence_base` (share of
clean clips per class with `silence_frac` >= each of 0.005, 0.02, 0.05,
0.1, 0.2, 0.3, 0.5), `clap_direction` (the 8 vocabulary texts and prompts
whose text embedding has the highest and the lowest cosine with the CLAP
head's direction coef / scale).

### R13. Held-out evaluation method

Each clip gets its score from a model trained without its group (leave one group
out), nor augmented copies of its clips. Schemes:

| Scheme | Held-out groups |
|---|---|
| A (headline) | one real category or one synth family at a time |
| A without augmentation | as A, no augmented training copies |
| A, CLAP head only / signal head only | ablations |
| B | synth groups split by generator type |
| C | the retired synthesized score never in any training set |
| D | the retired score and the synth engine never trained on |
| M (final grouping) | as A, music held out one provider at a time |

Metrics: ROC-AUC, accuracy at 0.5, Brier score, log loss; band coverage and
precision at the thresholds; calibration in 10 bins; per group and per
generator type; file level (mean of windows).

Robustness copies (scored only, never trained on): pink noise at -70 dBFS RMS
added to synthesized clips; a real room tone at -70 dBFS added to
synthesized clips; real clips gated to digital silence below -45 dB re peak;
0.15 s excerpts around the peak (both classes); MP3 128 kbps round trip (both
classes).

Level test (final model; it measures sensitivity, not accuracy). Each clip
is scored in 5 versions, all after the inference lift unless stated: at its
own level; 20 dB down; set to -25 dBFS RMS; set to -56 dBFS RMS with no
lift; set to -56 dBFS RMS with the lift.

Layer test: real 4 s beds, each with one code-synthesized layer added at
-12, -6, 0 or +6 dB (layer RMS over its own span, relative to the bed RMS).
They are labelled synthesized. The scoring model was trained without the
bed's group and without the layer's family.

## Data assets

### Realness model file: NEEDS-DATA

- Origin: trained (R12) on 1484 clean clips: real recordings (Freesound and
  Mixkit picks for one film, 366 accepted and 134 rejected-for-quality), 72
  windows of 7 professional launch films, 119 windows of professional music;
  synthesized: 318 clips of one synth engine (28 generator types, mixes,
  rendered scores), 260 clips of independent numpy generators (16 types, 14 clips each:
  beep, chord, chiptune, FM, pad, pluck, siren, DTMF, whoosh, riser, impact,
  wind, rain, click, LFSR noise, drums, plus code-made mixes with a
  Schroeder reverb and a limiter), 215 clips of a retired synthesized film
  score (stems, beds, melody, events).
- Why NEEDS-DATA: the real side needs a few hundred licensed real
  recordings, films and music that we do not have in the repo.
- Fallback 1 (no data, ship first): zero-shot CLAP score. score = LSE(38.7 ×
  cos(x, real prompts)) - LSE(38.7 × cos(x, synth prompts)), LSE =
  log-sum-exp. p_real = sigmoid(score). The source measured AUC 0.858,
  accuracy 0.749 at 0.5 for this baseline on all clean clips. The
  pure-tone rule applies unchanged. The verdict thresholds must be widened
  (proposal: lo 0.10, hi 0.90) and every summary must say the model is the
  zero-shot fallback.
- Fallback 2 (rebuild): train with R12 on a public corpus of real
  recordings (CC0 or CC-BY sound effects, ambiences and music with folder
  categories as groups) as positives, and our own forge recipe renders plus
  generic code generators (the 16 types above, written fresh) as negatives.
  Check against REA-14 to REA-16.
- The `trained` id must change with every retraining (it invalidates the
  result cache).

## Errors and edge cases

- Model file missing: an error naming the missing file and the training
  command. (surfaces then tells the user that real-vs-synthetic was not
  checked.)
- Bad range: R10 errors.
- Whole file silent, or every window silent: verdict `silent`, p_real null.
  No model is loaded for a silent file (signal check comes first).
- A clip shorter than 20 ms or with peak under 1e-7: not judged.
- Quiet source above -80 dBFS peak: lifted, never called silent because of
  its level alone (unless RMS stays at or below -60 after the lift).
- Many files: a decode failure becomes an error row; the batch goes on.
  Silent and error rows count separately and neither counts as real.
- In a call with several files, the range is used for each file.
- A cache entry that cannot be read is recomputed.
- Cached result: the `path` field is the path of the current call, not the
  first caller's spelling.

## Acceptance tests

- **REA-1** Model format. The model file parses as plain JSON; it has both
  heads with `mean`, `scale`, `clip`, `coef` of equal lengths (512 and 13);
  `fusion.heads` == ["clap", "signal"]; thresholds lo < hi; file lo >= clip
  lo; 6 + 6 prompts.
- **REA-2** Tone against recording. A 2 s 440 Hz sine at -12 dBFS: R3 gives
  tonal_frames >= 0.95, line_share >= 0.9, crest_db ≈ 3 dB; a 2 s
  white-noise burst with a 10 ms attack and exponential decay: tonal_frames
  < 0.1 and line_share < 0.1.
- **REA-3** Level does not matter. R3 of a clip and of the same clip 30 dB
  quieter: every value except `silence_frac` equal within 1e-6 relative.
- **REA-4** Not judged. A 10 ms clip and a clip of zeros -> R3 gives none; a
  clip with RMS -65 dBFS is not audible.
- **REA-5** Clips. 3 s -> 1 clip; 6.0 s -> 1 clip; 6.1 s -> 2 clips (0-4,
  2.1-6.1); 12 s -> 3 clips (0, 4, 8); 12.1 s -> 3 clips (the 4th, starting
  at 8.1, adds under 0.25 s and is dropped).
- **REA-6** Head and fusion. A head with mean [0, 0], scale [1, 2], clip
  [[-1, -1], [1, 1]], coef [1, 1], intercept 0; input [5, NaN] -> clipped
  and filled to [1, 0] -> logit 1.0. Fusion intercept 0, weights [1, 0] ->
  p = sigmoid(1.0) ≈ 0.731.
- **REA-7** Digital silence is never a reason. A clip that is 50 % exact
  zeros: no fact names silence; the silence line appears only in `evidence`,
  never in `why`.
- **REA-8** Silent file needs no model. A file of zeros: verdict `silent`,
  p_real null, `why` names exact digital silence; the CLAP model is not
  loaded.
- **REA-9** Pure-tone rule. A 30 s 440 Hz sine at -10.5 dBFS: every window
  is decided by the rule; mean p_real <= 0.03; verdict `likely
  code-synthesized`. (Source: the model alone gave 0.478 on this file.)
- **REA-10** Long file times. A 20 s file judged with `--start 4 --end 16`:
  `range` == [4.0, 16.0]; segments start at 4.0, 8.0, 12.0 (file times).
- **REA-11** Bad ranges. start -1, end 0 with start 0, start beyond the end
  -> value errors with the R10 messages.
- **REA-12** Many files. A folder with 1 sound, 1 silent file and 1 corrupt
  file, plus a missing path given -> `counts` has silent 1 and error 2;
  the CLI exits 1 before judging when a path is missing; without the missing
  path, it judges all and exits 1 because of the corrupt row.
- **REA-13** Quiet lift is smooth. A clip at -40 dBFS RMS with peak -28 dBFS
  -> gain = min(10, 27) = 10 dB; a clip at -45 RMS with peak -5 -> gain 4;
  a clip with peak -85 -> no gain; p_real of a clip and of the same clip
  20 dB quieter differ by less than 0.1 **[model]**.
- **REA-14** **[model]** Code beep. A 1 s 1 kHz square-wave beep with linear
  fade in and out -> verdict `likely code-synthesized` or p_real <= 0.3.
- **REA-15** **[model]** Held-out target (NEEDS-DATA). On a grouped
  leave-one-group-out run of a rebuilt model: ROC-AUC >= 0.90 (source:
  0.92 scheme A); at the chosen thresholds, both precisions >= 0.92 and
  coverage >= 0.75 (source: 0.924 / 0.922 / 0.79).
- **REA-16** **[model]** Real never fires the rule. Over every audible clip
  of a set of real recordings (source: 4741 clips of 345 recordings), the
  pure-tone rule fires 0 times.
