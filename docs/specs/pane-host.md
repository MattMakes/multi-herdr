# Pane Host Specification

`horch` drives one of two pane hosts per fleet: `herdr` (the `herdr` server behind the herdr TUI) or `hc` (`herdr-core` plus `herdr-app` behind the Herdr desktop app).

## Requirements

| ID | Requirement |
|---|---|
| HCB-01 | The backend is resolved once in `RuntimeContext` from `--backend`, else `HORCH_BACKEND`, else whichever single pane identity (`HERDR_PANE_ID` or `HC_TERMINAL_ID`) is set, else `herdr`; setting both pane identities without an explicit backend is refused as ambiguous, and `HerdrEnv.pane` reads from the resolved backend's variable. |
| HCB-02 | `Brief::transport_env` carries `HORCH_BACKEND` and any `HORCH_HC_BIN` / `HORCH_HERDR_APP_BIN` overrides to worker panes, while detached children scrub `HC_TERMINAL_ID`, `HC_SCOPE`, and `HORCH_BACKEND` alongside the starting pane's identity. |
| HCB-03 | `Execution` records and task ledger `workers` rows store `backend` (`herdr` or `hc`, defaulting to `herdr` and omitted from JSON when `herdr` so existing records keep their bytes), schema migration adds `workers.backend`, and `ExecutionStore::backend_of_workspace` returns the recorded owner of a workspace. |
| HCB-04 | Every host call outside `horch_core::workspace` goes through `PaneHost` (`of`, `for_backend`, `for_workspace`, `herdr_bin`), with no direct `Herdr::with_bin` or `workspace::herdr::Herdr` references outside `crates/horch-core/src/workspace/`, and `PaneHost::for_workspace` selects the workspace's recorded backend or falls back to `ctx.herdr.backend`. |
| HCB-05 | `HcApp` maps an `hc` terminal to `Pane` (`address` -> `pane_id`, `herdr.space` / `herdr.tab` labels -> `workspace_id` / `tab_id`, `status.app` / `status.state` -> `agent` / `agent_status`, `status_ms` -> `state_change_seq`), treats `state: "finished"` and exit `3` as gone, bounds `pane_list` (`hc ls` + per-terminal `hc get`) under a single deadline, maps `pane_read` and `wait_output`, and checks `core_socket` before running `hc server status` so reachability probes never start a core. |
| HCB-06 | `HcApp` maps `agent_prompt` and `pane_run` to `hc send --json`, `pane_send_keys` to `hc keys --json`, `pane_close` to `hc kill --json` followed by `hc rm`, refuses `pane_send_text` (`hc cannot type text without Enter`) and `report_agent` / `release_agent` (`hc agents report their own status`), treats `notification_show` as a no-op and `integration_status` as `None`, and `PaneHost` routes `Backend::Hc` to `HcApp` with `Caps { geometry: false }`. |
| HCB-07 | `HcApp` creates spaces, tabs, splits, and focus changes through `herdr-app do` (`space.new`, `space.close`, `tab.new`, `tab.select`, `pane.split` resolving the terminal's app pane id from `herdr-app ls`, `pane.focus`), reports a closed window on `workspace_create` (`the Herdr app window is not open; open Herdr and run this again`), refuses geometry operations (`pane_layout`, `pane_resize`, `pane_move`, `pane_move_new_tab`, `pane_focus`) with `Unsupported`, and refuses `tab_new` on `Backend::Herdr`. |
| HCB-08 | When `herdr-app` exits non-zero, `HcApp::pane_split` falls back to `hc run --bg --json --keep --no-parent` carrying the source terminal's `cwd`, `herdr.space`, and `herdr.tab` labels (producing a terminal with `parent: null` and `keep: true`), `workspace_close` falls back to closing every terminal labelled `herdr.space=<ws>`, and `workspace_list` / `tab_list` fall back to reading live terminals' labels under a single deadline. |
| HCB-09 | `workspace::place::place` is pure (`ARC-27`) and places spawned workers on hosts without geometry into 2 columns (cap 4) on tab 1 right of the orchestrator and 3 columns (cap 6) on overflow tabs named `workers <N>`, filling columns before rows in terminal-address order; when `!caps().geometry`, `after_change` and `settle_after_close` are no-ops, `tile` and `balance` report that the Herdr app arranges its own panes, and `layout` reports space, tabs, and terminals with status and without sizes. |
| HCB-10 | `Hosts::reachable` probes installed pane hosts without starting a core; state sweep judges each recorded workspace only against its recorded backend's host (keeping it when that host does not answer) and removes unrecorded folders only when `all_installed_answer` is true and no host lists them; watchdog/wake check workers on `row.backend`; listing commands union reachable hosts; and `horch telemetry ensure` / `restart_if_stale` keep one collector across hosts. |
