## Summary

This file lists the behavior of the current control plane that fleetd must keep or change on purpose. It covers the task lifecycle, the finish steps, worktrees, supervision, messaging, runs and context control. Code was read at worktree tip 99b05f19. "Design" is `ai_docs/plans/fleetd-design/source-design.md`. "decisions Dn" is `ai_docs/plans/fleetd-design/decisions.md`.

Rows: 73 behavior rows and 13 failure-mode rows. Design values over the 73 behavior rows: KEPT 14, CHANGED 40, NOT MENTIONED 19.

The `NOT MENTIONED` rows below cause lost work, a stuck fleet or a security problem if fleetd drops them. Most important first:

1. W6: cleanup and drop refuse while a `git stash` entry names the branch. A rescue ref (`git add -A` into a temp index) does not save stashes. Dropping this check loses stashed work.
2. F9: a land checks under the land lock, just before the fast-forward, that the task is still the worker's. A task cancelled during the rebase, the check or the lock wait lands nothing. Without it, cancelled work reaches the run branch.
3. F7: a red land resets the branch to its tip from before the rebase. Without it, a half-rebased branch stays, and the next attempt builds on a state that no check passed.
4. F5: a passed step stands only while the tree it judged is the tree now. New commits after a land reopen the land and later steps. Without it, unchecked commits land.
5. L5: `done --unlanded` parks the task with its worktree, and its dependents stay blocked. The design has no task-level park. Without it, the work of a task that cannot land is lost or its dependents start on missing work.
6. M5: a mail dir that another user owns or can write is refused, and mail dirs are mode 0700. Without it, another local user can plant lines that an agent reads as instructions.
7. W8: archive and trash refs only move forward, and each write is read back before a folder is removed. Without it, a ref write can overwrite other work, and a removal can follow a failed write.
8. F11: every git `fetch`, `ls-remote` and `push` has a wall-clock bound (push 10 min, others 3 min) and ssh/http stall limits. Without it, 1 stalled network call holds the land lock for hours. Two finish runs hung for more than 1 h 50 min on 2026-11-08.
9. S7: a reap ends the worker row and requeues the task before it signals any PID. The watchdog exits only between passes. Without it, the supervisor reports the kill as a crash, and a restart in the middle of a reap loses the requeue.
10. L6: a task owns files (`task_files` mode `own`), and no 2 running tasks own overlapping paths. Exclusive tasks (`parallel = 0`) run alone. The design plan has `outputs` but no exclusion. Without it, 2 workers of 1 idea edit 1 file at the same time.
11. W9: triage commits the uncommitted and untracked files of a folder before ARCHIVE or DELETE, refuses a detached HEAD at a unique commit, and deletes a branch only when the trash ref holds its tip. Without it, triage deletes work.
12. S8: `stop` refuses a worker of another host. Without it, a PID from another machine signals an unrelated local process.
13. L8: an operator requeue of a held task resets its attempt count (`attempt_floor`). The design has `max_attempts` but no reset. Without it, a task escalated once can never run again without a schema edit.
14. L9: `ledger unfinished`, `reopen` and `dismiss` keep a record of work that never landed. Without it, unlanded branches and worktrees from cancelled or reaped tasks are not listed for a decision.
15. S10: the watchdog restarts itself when its binary file changes (#216). The design does not say how a running fleetd moves to a new binary (gap 10 in decisions.md). Without it, fleetd runs old code after `horch self-update`.

Two `CHANGED` rows also need a check:

- S6: today the rule "never reap a worker that shows the usage-limit message" exists only in the orchestrator briefing (`teammates/_base/fleet-orchestrator.md:132`). No code enforces it, and the watchdog reaps such a worker after 3 stall rounds. Design FM-5 (design:787) ends an attempt at a rate-limit prompt after 5 min. decisions D2 replaces both with `waiting_quota`. The FM-5 text and D2 do not agree yet.
- S3: today a declared wait holds a worker up to 24 h (background) or 7 days (question). The design caps it at 1 h (design:515). The settled decision parks an exec worker that asks a question. The finish step's `background` wait of a detached finish has no row in the design.
