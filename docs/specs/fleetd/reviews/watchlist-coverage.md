## Uncovered lines

### Line 67 — T-892 early exit visibility

**Rank: no fault. Claim: verified.**

An attempt wrapper writes `exit.json` when its agent exits before `horch done` (`crates/horch-core/src/execution/lifecycle.rs:1106`). The pass treats that file as proof that the process is gone, runs rung 5, ends the attempt, and applies retry policy (`crates/horch-core/src/fleetd/fleet_runtime/application/pass.rs:2171`). The end-to-end test proves that an agent which exits without a result becomes worker `incomplete`, and its task returns to `ready` or `queued` without waiting for lease expiry (`crates/horch-e2e/tests/p5_push_attempt_process.rs:337`). The attempt, worker, and queued task remain visible to the operator. Removing the synthetic `BLOCKED` message avoids falsely classifying an ordinary early exit as a user question.

### Line 77 — T-900 push-dispatched review contract

**Rank: Important. Claim: verified. Finding: R7-F1.**

The T-900 contract is not implemented on this worktree. A pushed reviewer still runs as a review task with no worktree of its own. A plain `horch result` derives commits and files from that task's worktree and refuses when none exists (`crates/horch/src/cmd/resultcmd.rs:124`, `crates/horch/src/cmd/resultcmd.rs:164`). The claim-mode path knows that review tasks have no finish steps and ends them through `horch ledger done` after checking the findings file (`crates/horch-core/src/taskledger/finish/mod.rs:741`, `crates/horch-core/src/taskledger/finish/mod.rs:1221`), but fleetd's verifier has no equivalent review-task completion path. The end-to-end failure `the_whole_flow_on_the_fake_herdr` remains listed at `crates/horch-e2e/expected-failures/taskledger.txt:8`, and the required `crates/horch-e2e/tests/p4_review_push.rs` does not exist.

The required contract is: run the reviewer against a read-only view of the reviewed task's worktree; permit only its findings file as output; ingest that findings file as the review verdict; end the review task `done` without a `task_check`, nested review, commit, or worktree; then let the reviewed task's unchanged code-sweep step consume the verdict. Until that path exists, a light or full review can hold its parent task in `verifying` indefinitely.
